# ربط القالب الموحد بلوحة الإدارة ومسار النشر — الحالة الفعلية

آخر تحديث: 2026-10-31  
الحالة: مدمج في `main` عبر PR #398، وEdge Function الحية بالإصدار 14.

## مصدر الحقيقة

- الحزمة الكاملة `KHALEDOON_STORY` المحفوظة في `story_meta.story_package` هي مصدر الحقيقة للحكايات الجديدة.
- `v2ToAdminDraft` ينشئ إسقاطًا متوافقًا مع حقول لوحة الإدارة القديمة للعرض والتحرير الإداري فقط. لا يُستخدم هذا الإسقاط لبناء صفحة القارئ أو ملفات النشر.
- يحتفظ سجل الإدارة بالحزمة الأصلية كاملة، ولا يجوز إعادة بناء القالب الموحد من إسقاط V1 أو فقد حقولها.
- حكايات V1 المنشورة تظل على صفحاتها الحالية حتى ترحيل مستقل ومراجع؛ لا تُحوّل تلقائيًا عند فتح لوحة الإدارة.

## مسار الحكاية الجديدة

1. يستورد الأدمن حزمة القالب الموحد؛ يتحقق المدقق من العقد واللغات والصور والأسئلة ومعلومات الخريطة.
2. تُحفظ الحزمة الأصلية كاملة في سجل الإدارة، مع إسقاط إداري غير مرجعي لحقول العرض القديمة.
3. تُعرض المعاينة وتظل الحكاية مسودة حتى يراجعها الأدمن ويعتمدها صراحةً.
4. بعد الاعتماد، ينشئ `rebuild/publish-story.mjs` ملفات النشر من حزمة القالب الموحد المحفوظة نفسها، ويتحقق من الفهرس والمسارات وعدم تكرار الحكاية ووجود الصور المحلية.
5. يرسل زر «نشر الحكاية» الملفات إلى Edge Function `publish-story-pr`.
6. تتحقق الوظيفة من هوية الأدمن وسجل الحكاية وموافقة المعاينة وتطابق `story.json` مع الحزمة المحفوظة، وتراجع اتساق صفحة القارئ والفهرس والترجمات وبنك الأسئلة والخريطة.
7. تنشئ الوظيفة فرعًا وطلب دمج GitHub؛ لا تكتب مباشرة إلى `main`.
8. بعد مراجعة PR ودمجه، ينشر GitHub Pages الملفات. يعود الأدمن للتحقق من الصفحة الحية قبل تغيير حالة السجل إلى منشور.

## ملفات النشر الناتجة

- `index.html`: صفحة القارئ الموحد.
- `story.json`: حزمة القالب الموحد الأصلية.
- `data.json`: بيانات التوافق والفهرس.
- `sources.md`: مصادر الحكاية.
- `original.md`: النص الأصلي كما وصل.
- `stories/quizzes/{id}.json`: بنك الأسئلة باللغات الخمس.
- `stories/index.json`: فهرس الحكايات.
- `stories/places.json`: بيانات الخريطة، بما فيها `null` الصريح عند عدم وجود موقع موثق.

## حدود الأمان

- Edge Function الحية `publish-story-pr` بالإصدار 14، و`verify_jwt=true`.
- مصدر الوظيفة الحية مطابق لملف `supabase/functions/publish-story-pr/index.ts` في `main`.
- تتطلب الوظيفة جلسة مستخدم صالحة ونتيجة `is_admin() = true` وسجل إرسال معروفًا.
- لا يُقبل ملف القالب الموحد إلا إذا طابق الحزمة المحفوظة والمعتمدة؛ لا يُقبل قرار اعتماد قادم من ملف المحتوى نفسه.
- لا تُكشف أسرار GitHub في المتصفح؛ يستخدم الناشر السر المحفوظ في Supabase.
- لا تغييرات على مخطط Supabase أو سياسات RLS مطلوبة في هذا التكامل.
