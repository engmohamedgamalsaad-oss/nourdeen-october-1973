## قواعد العمل غير القابلة للتجاوز

1. لا دمج ولا نشر إلى الموقع قبل موافقة صاحب المشروع الصريحة.
2. لا تغييرات في Supabase أو SQL أو migrations أو RLS أو الصلاحيات أو الدوال المنشورة دون موافقة صريحة.
3. لا حذف للفروع أو إغلاق لطلبات الدمج أو إعادة كتابة تاريخ Git دون موافقة.
4. لا تدّعِ أن اختبارًا شُغّل إذا كانت النتيجة منقولة من CI فقط.
5. اعتمد على الملفات والـSHA والحالة الفعلية الحالية، لا على الذاكرة أو تقارير قديمة وحدها.
6. فضّل تغييرات صغيرة قابلة للمراجعة والتراجع، مع الحفاظ على الحكايات والروابط والخريطة والصور وQR والمشاركة والطباعة والأسئلة والتفاعلات.
7. عند كل تسليم، حدّث الحالة والدليل والملفات والاختبارات والخطوة التالية، وسجّل ما لم يتم التحقق منه.
8. «كمل» ليست موافقة على الدمج أو النشر.
