# تحليل الموقع المرجعي: مسارات المستقبل — أفكار الحركة والتفاعل لخالدون

تاريخ الفحص: 2026-10-28  
الموقع المرجعي: https://future-pathways.net/#spread  
المسودة المرتبطة: PR #396 — `feature/khaledoon-cinematic-world-experience-20261028`

## الهدف والحدود

الهدف هو فهم التقنيات والأنماط البصرية التي تمنح الموقع المرجعي إحساسًا بالحركة والعمق، ثم تطبيق أفكار مناسبة على «خالدون عبر التاريخ» مع الاحتفاظ بهوية خالدون الحالية، وألوانه، وتصميم أقسامه، وأسلوب كل حكاية. هذه مذكرة تحليل وتوجيه تنفيذ، وليست نقلًا لتصميم الموقع أو شفرته.

## ما أمكن التحقق منه في الأرشيف

الأرشيف المحلي يحتوي صفحة HTML محفوظة وملف CSS مجمّع وملف JavaScript رئيسيًا مجمّعًا. كما يشير HTML إلى ملفات خارجية محمّلة من الموقع الحي، منها وحدة باسم `globe-…js` ومكتبة `three-…js`. هذه الملفات الخارجية لم تكن موجودة ضمن الأرشيف؛ لذلك لا يمكن تأكيد تفاصيل تنفيذ المجسم الكروي بالكامل من الأرشيف وحده.

### 1. الكرة الأرضية / المشهد ثلاثي الأبعاد

- الصفحة تحمل إشارات تحميل واضحة لوحدة globe ولمكتبة Three.js، ما يدعم أن الكرة التفاعلية مبنية على مشهد WebGL/Three.js أو تعتمد عليه.
- عناصر المشهد تتعامل مع السحب بالماوس/اللمس، ويظهر في CSS استخدام `touch-action: none` ومؤشر السحب، وهي تفاصيل مناسبة لعنصر تفاعلي لا لصورة ثابتة.
- توجد طبقة إرشاد للمشهد وطبقة pulse حول الكرة؛ النبض ينفّذ بتغيير الشفافية والحجم بصورة دورية.
- في خالدون، الكرة الحالية مرسومة على Canvas بأسلوب زخرفي. لا ينبغي وصفها بأنها كرة جغرافية دقيقة أو مجسم Three.js حقيقي. إذا أردنا ترقية لاحقة، يجب مقارنة تكلفة وحجم Three.js وبيانات الخرائط مع فائدة التجربة قبل إدخال مكتبة ثقيلة.

### 2. دخول العناوين والمحتوى

- يوجد انتقال دخول قصير لعبارات الواجهة باستخدام الشفافية والحركة الرأسية الخفيفة، بدل ظهور مفاجئ.
- CSS يحتوي قواعد لحركات مثل دخول العبارة وإشارة التمرير، مع إيقاف أو تبسيط الحركة عند تفعيل `prefers-reduced-motion`.
- ملف JavaScript المجمّع يحتوي على مؤشرات كثيرة إلى GSAP، كما توجد إشارات إلى `requestAnimationFrame` و`IntersectionObserver`. هذا دليل على وجود أدوات للأنيميشن والتحديثات الإطارية ومراقبة ظهور العناصر، لكنه لا يكفي وحده لنسبة كل تأثير إلى أداة بعينها.

**التطبيق المقترح في خالدون:** ظهور تدريجي محدود للعناصر المهمة عند دخولها مجال الرؤية، مع انتقال قصير وهادئ. يجب أن يظل النص قابلًا للقراءة فورًا، وألا تعتمد الحكاية أو روابطها على اكتمال الأنيميشن.

### 3. الصور والبطاقات والعمق

القواعد المرئية في CSS تتضمن مجموعة من التقنيات التي يمكن إعادة توظيفها بصورة مستقلة عن التصميم الأصلي:

- تحريك الصورة داخل حاوية مقصوصة، مع تكبير أولي خفيف ثم العودة إلى المقياس الطبيعي.
- استخدام `transform` و`filter` لتغيير المقياس والسطوع والتدرج الرمادي في حالات التفاعل.
- استخدام ظلال واسعة وطبقات شفافة لتكوين عمق، دون الحاجة إلى تغيير بنية البطاقة نفسها.
- انتقالات قصيرة للحواف والخلفيات والظلال واللون.
- استخدام `backdrop-filter: blur(...)` لبعض العناصر الشفافة، ويجب قصره على مساحات صغيرة حتى لا يثقل الهاتف.
- تراكب الصورة والنص والطبقات الزخرفية داخل حاوية ذات حدود واضحة، مع الحفاظ على قص الصورة داخل البطاقة.

**التطبيق المقترح في خالدون:** إضافة حركة hover خفيفة للصور والبطاقات على الأجهزة التي تدعم المؤشر، وحركة دخول لطيفة على الهاتف. لا نضيف تكبيرًا مبالغًا فيه، ولا نحرك كل الصور في الوقت نفسه، ولا نغيّر صورة الغلاف أو أسلوب القسم أو تخطيط الحكاية.

### 4. التفاعل مع التمرير

- توجد إشارات واضحة إلى سلوكيات التمرير وإلى مراقبة ظهور العناصر؛ بعض العناصر تستخدم `will-change` لتحسين الحركة.
- تظهر أيضًا معالجة صريحة لتفضيل المستخدم تقليل الحركة، بما في ذلك إلغاء بعض الانتقالات والأنيميشن.
- ينبغي أن تكون الحركة مرتبطة بظهور العنصر أو بتفاعل المستخدم، لا بتشغيل مؤثرات مستمرة على الصفحة كلها.

**التطبيق المقترح في خالدون:** كشف تدريجي للعناصر عند ظهورها، مع حارس يمنع إعادة تشغيل الحركة بلا داعٍ، وتعطيلها أو تقليلها عند تفعيل تقليل الحركة. نتجنب إضافة مكتبة جديدة إن كان CSS وJavaScript الموجودان يحققان المطلوب.

### 5. الحركة الدقيقة والتغذية البصرية

الموقع المرجعي يستخدم انتقالات قصيرة لحالات الأزرار والروابط والعناصر التفاعلية، وإشارات بصرية بسيطة توجه المستخدم إلى وجود تفاعل. توجد أيضًا حركة نبض حول عنصر الكرة وإشارة تمرير متحركة.

**التطبيق المقترح في خالدون:** حالات hover/focus/active واضحة، نبض هادئ للنقاط التفاعلية على الكرة عند الحاجة، وتلميح واحد يشرح إمكانية السحب أو الاختيار. يجب توفير `focus-visible` للوحة المفاتيح، وعدم جعل الحركة الوسيلة الوحيدة لفهم التفاعل.

### 6. اللغات والتجاوب وإتاحة الاستخدام

- الأرشيف يوضح أن الصفحة تدعم العربية واتجاه RTL، وتحتوي تبديلًا إلى الإنجليزية.
- قواعد CSS تتضمن معالجة صريحة لـ `prefers-reduced-motion`، وتغييرات خاصة بالشاشات الصغيرة.
- يجب اختبار التأثيرات مع اتجاهي RTL/LTR، وفي الوضعين الفاتح والداكن، وعلى الهاتف والكمبيوتر.
- الحركة لا يجوز أن تسبب قفزات في التخطيط، أو تخفي أزرار التحكم، أو تعطل التمرير واللمس.

## ما لا يمكن تأكيده من الأرشيف الحالي

1. لم تُحفظ ملفات الكرة الخارجية وملف Three.js المشار إليهما في HTML، لذلك لم يتم تدقيق كود الكرة نفسه أو إعدادات المشهد والخامات والأضواء.
2. لا يمكن استنتاج الأداء الفعلي على هاتف متوسط من ملفات CSS وJavaScript وحدها.
3. لم تُثبت مراجعة الأرشيف أن كل حركة في الصفحة نُفذت بواسطة GSAP؛ وجود المكتبة في الملف المجمّع لا يعني أنها مسؤولة عن كل التأثيرات.
4. لا ننسخ الأصول البصرية أو الشعار أو النصوص أو الشفرة الخاصة بالموقع المرجعي. نعيد تنفيذ الأنماط العامة بأسلوب خالدون.

## خطة تطبيق الأفكار على خالدون

### المرحلة A — ضمن المسودة الحالية

- الاحتفاظ بالكرة الحالية كعنصر تفاعلي زخرفي، وعدم الادعاء بأنها خريطة جغرافية دقيقة.
- استخدام بيانات القصص المنشورة والمواقع المعروفة في المشروع فقط؛ لا نولّد إحداثيات أو روابط مكانية غير موثقة.
- مراجعة ظهور الكرة وحالات اختيار النقاط، والتأكد من أن كل نقطة مرتبطة بقصة صحيحة وأن النصوص مترجمة للغات الخمس المستخدمة في خالدون.
- إضافة كشف تدريجي خفيف لعناصر الصفحة الرئيسية، مع عدم إعادة تصميم الأقسام أو تغيير ألوانها أو ترتيبها.
- تطبيق حالات تفاعل هادئة للبطاقات والصور: تكبير بسيط للصورة داخل الحاوية، انتقال ظل/حدود، وتغذية بصرية للأزرار.
- احترام `prefers-reduced-motion` وتقليل الحركة على الأجهزة الصغيرة أو عند الحاجة.
- الحفاظ على دعم اللمس ولوحة المفاتيح والوضعين الفاتح والداكن واللغات AR/EN/FR/IT/DE.

### المرحلة B — بعد التحقق البصري

- فتح معاينة المسودة على هاتف وكمبيوتر ومقارنة التأثيرات بالموقع الحالي، لا بالمرجع فقط.
- التأكد من عدم حدوث تداخل مع القوائم، ورأس اللغة الثابت، وبطاقات القصص، وأسلوب كل قسم.
- قياس أي تكلفة أداء قبل إضافة Three.js أو أي مكتبة أنيميشن جديدة. لا نضيف اعتمادًا جديدًا لمجرد التشابه البصري.
- إذا كان المطلوب لاحقًا مجسمًا جغرافيًا حقيقيًا، نقرر ذلك كمهمة منفصلة بعد تحديد مصدر بيانات جغرافية موثوق وحجم الملفات وتوافق الترخيص.

## قائمة قبول قبل دمج المسودة

- [ ] لا تغييرات على بيانات القصص أو Supabase أو آلية النشر.
- [ ] لا استبدال لهوية خالدون أو قوالب الحكايات الحالية.
- [ ] لا إحداثيات أو نقاط قصص غير موثقة.
- [ ] لا أخطاء JavaScript عند اختيار نقطة أو فتح قصة.
- [ ] لا أخطاء في RTL/LTR أو في اللغات الخمس.
- [ ] الصور والبطاقات لا تسبب قفزات في التخطيط.
- [ ] الحركة تعمل على الهاتف والكمبيوتر، ويمكن تقليلها من إعدادات النظام.
- [ ] اختبار روابط القصص الفعلية ونتائج CI قبل اعتبار المسودة جاهزة.
- [ ] المسودة لا تُدمج ولا يُنشر الموقع الحي تلقائيًا.
