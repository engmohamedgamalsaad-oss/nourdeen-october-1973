# نسخة Gemini — تجهيز حكاية خالدون

ابدأ بقراءة `PROJECT_INSTRUCTIONS.md` و`docs/khaledoon-story-production-workflow.md` وتعليمات المستودع، ثم افحص القالب الحالي والحكايات المرجعية والفرع والملفات المرتبطة. لا تفترض أن أسماء الملفات أو المسارات القديمة ما زالت صحيحة، ولا تفترض أن لديك وصولًا فعليًا إلى GitHub أو الملفات أو المتصفح لمجرد أنك Gemini.

نفّذ دورة تجهيز الحكاية كاملة حتى صفحة معاينة مستقلة مطابقة للقالب الحالي. استخدم الأدوات المتاحة فعليًا فقط، واعمل على فرع منفصل، وافحص الفروقات والاختبارات. إذا لم تتوفر صلاحية الكتابة أو الاختبار أو الرفع، صرّح بذلك وأخرج الملفات كاملة بمساراتها الدقيقة وخطوات الرفع اليدوية بدل ادعاء التنفيذ. لا تحذف أو تستبدل ملفات قائمة دون ضرورة واضحة، ولا تغيّر قاعدة البيانات أو تنشر الحكاية دون موافقة صريحة من صاحب المشروع.

## المحتوى والدقة التاريخية

- احتفظ بالنص الأصلي كما وصل، دون تعديل، في حقل أو ملف منفصل عن النسخة المحررة.
- تحقّق من الأسماء والتواريخ والوقائع والسياق التاريخي بمصادر موثوقة. ميّز المختلف عليه أو غير المؤكد، ولا تخترع وقائع أو مصادر أو روابط.
- اجعل كارما طفلة فضولية بصوت مناسب لعمرها، تطرح أسئلة وتبدي ملاحظات واستنتاجات معقولة؛ واجعل الراوي صوتًا بالغًا يشرح التاريخ بالأدلة والسياق. لا تخلط الصوتين.
- جهّز العربية الأصلية والترجمات الفعلية إلى الإنجليزية والفرنسية والإيطالية والألمانية (AR/EN/FR/IT/DE). راجع المعنى والعناوين والأزرار والتواريخ وتسميات الصور واتجاه الكتابة لكل لغة.
- أضف بنك اختبار لا يقل عن خمسة أسئلة، مع الاختيارات والإجابة الصحيحة والتفسير، وترجم جميع عناصره إلى اللغات المطلوبة.
- حافظ على وظائف الموقع القائمة: التفاعلات والإعجاب وردود الفعل والمشاركة عبر WhatsApp وFacebook والطباعة والتنقل، والتصميم المتجاوب، وRTL، والوضعان الفاتح والداكن. لا تكرر وظائف موجودة ولا تعِد التصميم من الصفر.

## الصور والمصادر

- اقرأ الحكاية وافهم سياقها قبل اختيار الصور.
- لا تستخدم صورة مولدة بالذكاء الاصطناعي على أنها صورة تاريخية حقيقية.
- تحقّق من المصدر والترخيص وشروط الإسناد لكل صورة. إذا تعذر التوثيق، وضّح ذلك واختر بديلًا توضيحيًا مناسبًا عند الحاجة.
- اتبع مخطط الصور في القالب الحالي، بما يشمل رابط الصورة والنص البديل والتعليق ونوع الصورة واسم المصدر ورابطه وحقوق الاستخدام. لا تضع روابط وهمية، ولا تكرر الصورة نفسها لتلبية الحد الأدنى المطلوب.
- جهّز الغلاف وصورة شاشة البداية/النافذة المنبثقة وفق القالب الحالي، وتحقق من وجود الملفات وصحة الأبعاد والامتدادات والمسارات. لا تضف صورة إلى الموقع قبل التحقق من وجودها وصحة مسارها.

## حزمة JSON والخريطة التفاعلية

إذا كان التسليم عبر حزمة JSON، أخرج كائن JSON صالحًا واحدًا فقط داخل كتلة `json` دون أي نص قبله أو بعده. يجب أن تكون `format` أول خاصية في كائن JSON الجذر، وبالقيمة التي تحددها تعليمات المشروع الحالية. التزم بالمخطط الحالي حرفيًا، بما يشمل `section_key` و`translations` و`question_bank` و`images` وأي حقول إلزامية أخرى. لا تحذف حقولًا إلزامية ولا تضف تعليقات أو فاصلات زائدة.

- ضمّن `map_location` صراحةً: إما `null` إذا لم يتوفر موقع جغرافي موثوق مناسب، أو بيانات مكان موثقة وفق المخطط الحالي، مع إحداثيات ومصادر موثوقة عند اشتراطها. لا تخترع الإحداثيات.
- يجب أن تمر بيانات الموقع الموثقة عبر آلية المشروع لربط الحكاية تلقائيًا بالخريطة التفاعلية، مع الحفاظ على العلامات والأماكن الموجودة وعدم استبدالها أو حذفها. لا تعتبر وجود الحقل وحده دليلًا على نجاح الربط؛ افحص مسار المعالجة والاختبارات المتاحة.
- راجع صحة JSON ومطابقته للمخطط قبل التسليم. لا تدّعِ أن الاستيراد نجح ما لم يتم التحقق منه.

## هيدر الحكاية وقسم الـ hero (إلزامي، لا تكتب له CSS)

التنسيق المشترك في `assets/shared/story-layout.css` ويُحمَّل تلقائيًا عبر `assets/shared/base.css`، فلا تكتب أي CSS للهيدر أو الـ hero داخل `index.html` أو `theme.css`. التزم بالبنية التالية فقط:

- يحمل `body` الخاصية `data-story-slug` وكلاس `story-design-…`، ويكون أول عنصر داخله `<header>` مباشرة، وفيه رابط القسم ورابط الرئيسية وعنصر `.language-switch`.
- قسم البطل: `<section class="hero">` يحتوي `<div class="hero-art"><img …></div>` ثم `<div class="container">` بهذا الترتيب.
- لا تضع صورة البطل بتموضع مطلق، ولا تحدد ارتفاعات أو هوامش للهيدر أو الـ hero.
- لا تثبّت ألوان الخلفية أو النصوص باستخدام `!important`؛ الوضعان الفاتح والداكن يأتيان من `assets/shared/khaledoon-theme-stories.css`.

بعد الإنهاء افحص صفحة الحكاية في الوضعين الفاتح والداكن على الكمبيوتر والهاتف، وتأكد أن النص لا يتداخل مع الصورة وأن الهيدر واضح.

## التكامل والاختبار والاعتماد

- استخدم قالب القسم الحالي والملفات المشتركة بدل إنشاء تصميم جديد أو تكرار وظائف قائمة. افحص أثر أي تعديل مشترك على الصفحة الرئيسية والحكايات الأخرى.
- اختبر الروابط والصور والترجمات والأسئلة والخريطة والوظائف المشتركة قدر الإمكان، واذكر بدقة الاختبارات التي نُفذت فعلًا ونتائجها. لا تقل إن الاختبارات نجحت إذا لم تشغّلها.
- جهّز صفحة معاينة للحكاية وحدها، واعرضها على صاحب المشروع مع ملخص ومصادر وحقوق الصور والملفات المعدلة وأي نقاط غير مؤكدة.
- تبقى الحكاية مسودة حتى يوافق صاحب المشروع صراحةً. لا تنشرها ولا تمنحها رقمًا نهائيًا قبل الاعتماد والتحقق من الرقم التالي المتاح.
- لا تعتبر إنشاء ملف أو commit أو دمج طلب نجاحًا للنشر الحي؛ تحقّق من ظهور النسخة المنشورة فعلًا قبل الإبلاغ عن النشر.
