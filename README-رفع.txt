خالدون عبر التاريخ — حزمة المعاينة

المسارات:
- khaledoon/index.html: الصفحة الرئيسية المستقلة.
- khaledoon/collections/curriculum.html: تصفح حكايات المناهج المنشورة.
- khaledoon/submit.html: نموذج إرسال المقترحات.
- khaledoon/admin.html: لوحة مراجعة وتحرير ونشر المقترحات (لا تُشارك رابطها للعامة).
- khaledoon/assets/: التنسيقات والوظائف المشتركة.
- docs/khaledoon-supabase.sql: إعداد جدول خالدون وسياساته وواجهة القراءة العامة.

قبل تشغيل الإرسال والنشر:
1) راجع إعداد Supabase القديم في docs/supabase-setup.sql؛ يجب أن يكون جدول admins ودالة public.is_admin() موجودين، وأن يكون حساب المسؤول مسجلًا بالبريد الصحيح.
2) افتح Supabase SQL Editor وشغّل docs/khaledoon-supabase.sql بعد مراجعة محتواه. لا تشغّل ملف إعداد خالدون على قاعدة إنتاج قبل التأكد من المشروع الصحيح.
3) صفحة الزوار تقرأ من view اسمها public.khaledoon_published، وهي تعرض الحكايات المنشورة فقط ولا تكشف اسم الراوي أو صفه أو النص الأصلي أو ملاحظات الإدارة.
4) اختبر إرسال مقترح، ثم تسجيل دخول مسؤول، ثم حفظه ونشره، ثم افتح صفحة المناهج في نافذة خاصة للتأكد من ظهوره. اختبر الرفض والحذف أيضًا.
5) لا تضع service_role أو أي مفتاح سري في ملفات HTML/JavaScript. مفتاح sb_publishable الظاهر في الواجهة ليس سرًا؛ الحماية تعتمد على RLS وسياسات Supabase.
6) يوجد حدّ إرسال على مستوى قاعدة البيانات: 5 مقترحات لكل بصمة IP خلال 10 دقائق، مع تخزين بصمة MD5 بدل عنوان IP الخام. حدّ المتصفح والـ honeypot طبقتان إضافيتان فقط، وليسا بديلًا عن حدّ الخادم.
7) رابط المعاينة المقترح بعد تفعيل GitHub Pages:
https://engmohamedgamalsaad-oss.github.io/nourdeen-october-1973/khaledoon/
تأكد من فتح الرابط الفعلي قبل استخدامه أو طباعة QR.

الفصل عن موقع نوردين:
- لا تغيّر هذه الصفحات جدول submitted_stories القديم ولا صفحات الحكايات المنشورة أو رموز QR الحالية.
- صفحة خالدون تستخدم جدول khaledoon_submissions وواجهة khaledoon_published المنفصلين.
- لا تعتبر دورة الإرسال والنشر مكتملة قبل اختبار Supabase الفعلي؛ تعديل الملفات وحده لا ينشئ الجداول على المشروع السحابي.
