# attempt_AI_eye_opening_clearance_on_AH
Narrow repair on the AH GLBs (new folder; AD..AH untouched). NOT a likeness step. Code src/fix_eye_v2.py.
Why: AH eye close-ups show a jagged notch where the skin cuts into the eyeball at the outer corner, and Muse's exported-mesh validator (muse/karma-custom-topology-face-test-2026-11-25 @ 0e204be4, copied unchanged in src/, I re-ran it) flags 183 candidate "opening penetration" pairs under ITS heuristic (reproduced; its rule not audited by me). Sphere assumption verified on the mesh: centres (+-.5, .01, -.03), r .30.
Change: skin vertices inside either eye sphere (+.015 margin) within 60 deg of +z from the eye centre are pushed radially out to r .315. 50 vertices per file moved, max move .0487 file units (some of these skin vertices were deep inside the sphere).
Visual check: evidence/eye_closeup_front_35deg_AH_left_AI_right.png (front and 35 deg, AH left, AI right). The jagged outer-corner notch is gone, the lid opening is a cleaner almond; the lid margin is slightly thicker. I judge this a defect fix, not a shape improvement.
Numbers on these exports: Muse script AH 1,930 pairs (1,747 contact, 183 candidate) -> AI 1,160 pairs (1,160 contact, 0 candidate). My own validity test (older, less strict method) 1,762 -> 1,068 eyeball-skin pairs; skin self-intersection 0, teeth vs skin 0 (smile). Per-triangle vs AH: flipped 0, 4 turned over 60-90 deg, min area ratio .672, none under .25.
Limit: the 0 "candidate" result is relative to Muse's rule, which I haven't audited; the pixel inspection is what supports the fix.
